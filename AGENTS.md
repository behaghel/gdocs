# Coding guidance

- Follow the [semantic encapsulation contract](README.md#semantic-encapsulation) when changing conversion or diff behavior. Feature policy belongs in feature modules, not generic algorithms; preserve the architecture and behavioral regression tests.
- Separate semantic conversion, presentation policy, diffing, transport/authentication and asynchronous orchestration. Resolve configurable presentation through logical styles (`gdocs-styles.el`); do not hardcode personal typography into conversion or diff policy. Preserve authored emphasis, link targets and semantic colours rather than mistaking them for disposable presentation.
- Cover semantic features in both directions and through the full local pipeline, not only isolated helpers: Org → IR → requests and Docs JSON → IR → Org, create/push planning, repeated/no-op diffs, edits, failure cases and UTF-16 indices. Cover originating buffer/account preservation when callbacks or uploads are involved. Keep focused feature fixtures alongside broad regression tests.
- Use the standard document specimens (`test/fixtures/kitchen-sink.org` and `test/fixtures/kitchen-sink.json`) to detect regressions across supported constructs. Extend specimen coverage with feature changes; make unsupported/lossy cases explicit and fail closed. Representative fixture JSON is not evidence of live API acceptance. Consumer integration also exercises its own standard typographic specimen; the gdocs library must not depend on a personal checkout or private document.
- CI must run standard-specimen non-regression tests (`make test-specimen`), the full suite (`make test`) and strict byte compilation (`make compile`) for reviewed changes. A supported-case regression blocks integration. Do not weaken assertions, bless changed output or add expected failures merely to turn CI green; investigate and explicitly resolve changed semantics.
- Treat detected fidelity loss as a defect to correct, not a compatibility behavior to preserve. Inherited expected failures do not exempt a slice from correction. Add an ordinary failing regression, fix the loss, and distinguish missing/obsolete fixture assertions from runtime defects. Content fidelity takes precedence over unchanged output fingerprints; explain and test intentional corrections rather than preserving defective output.
- Keep authored emphasis separate from presentation; follow the [quote reversibility contract](README.md#quote-block-conversion), including applied-style provenance and fail-closed import.
- Prefer small, explicit module contracts and ordinary Emacs facilities over custom registries, discovery or declaration DSLs.
- Keep changes scoped and preserve this repository's space-indented Elisp style.
- Run `make compile` and `make test` with the project's declared dependencies. Retain configured commit signing; never bypass failed checks or signing.
